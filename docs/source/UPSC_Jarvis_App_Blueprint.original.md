# **UPSC JARVIS: Open-Source GitHub Repositories aur Vibe Coding par Aadharit Unified AI Ecosystem ka Blueprint**

Civil Services Examination (UPSC CSE) ki taiyari mein sabse bada bottleneck content ki kami nahi, balki information overload, fragmented resources, aur passive reading ki aadat hai. Ek non-traditional developer ya aspirant jise "vibe coding" (AI coding agents jaise Gemini Pro par aadharit Antigravity, OpenCode, Claude Code, ya Cursor ke madhyam se natural language prompts dekar software assemble karna) aati hai, uske liye zero se har module code karna avyavaharik hai. Sabse saral aur prabhavi rasta "Modular Repo-Stitching Architecture" hai, jismein pehle se maujood battle-tested GitHub repositories ko ek single desktop wrapper (Electron.js \+ React frontend aur Python FastAPI local backend) ke andar unify kiya jata hai. Yeh report ek aise local-first, zero-cost, gamified "UPSC JARVIS" application ka end-to-end technical aur pedagogical blueprint prastut karti hai jo student ki buri aadaton ko todkar use ek top-ranker ke anushasan (discipline) aur analytical precision ke saath train karta hai.

## **Vibe Coding Architecture aur Zero-Cost AI Orchestration**

Ek vibe coder ke liye sabse badi chunauti alag-alag programming languages aur frameworks ko manually jodna hota hai. Is samasya ko hal karne ke liye application ki base foundation ke roop mein Sachin23991/upsc-os aur thisisAtharv/ExamEdge jaise existing full-stack UPSC repositories ko primary UI template ke taur par clone kiya ja sakta hai. upsc-os pehle se hi React, Tailwind CSS, Framer Motion, Recharts, Three.js, aur Google Generative AI ke saath ek smart dashboard, syllabus manager, study planner, rich text notepad, aur interactive quiz system pradan karta hai. Is poore ecosystem ko chaar interconnected horizontal architectural layers mein vyavasthit kiya jata hai taaki data flow aur inter-process communication (IPC) bina kisi manual coding complexity ke kaam kare. Pehli layer **Electron Desktop Shell & UI Layer** hai, jiske andar upsc-os ka main dashboard aur planner, ahrm/sioyek par aadharit split-window PDF reader, ad-blocked YouTube \<webview\>, aur OpenPetsHQ/openpets ka 2D desktop companion rehta hai. Doosri layer **Zero-Cost AI Orchestration & Browser Gateway** hai, jo QuantumNous/new-api local router, iFurySt/open-browser-use web agent (Gemini Pro, Claude, aur ChatGPT web sessions ke liye), aur local Ollama SLMs (Phi-3 Mini tatha Sarvam-1) ko संचालित karti hai. Teesri layer **Persistent Second Brain & Graph Storage** ki hai, jismein HKUDS/LightRAG knowledge graph (PostgreSQL pgvector aur Apache AGE par aadharit) tatha local Obsidian Markdown vault (obsidian-spaced-repetition-recall ke saath) student ke saare study records ko permanently store karte hain. Chauthi aur sabse nichli layer **Specialized Python FastAPI Microservices** (localhost:8000) ki hai, jo Telethon Telegram PDF crawler, Surya aur Chandra handwriting OCR, MediaPipe interview computer vision, Whisper audio prosody analyzer, aur Pathway/PIB current affairs streaming engine ko background mein orchestrate karti hai.

### **Unified Free AI Quota aur Browser Automation Layer**

Har AI platform (Claude, ChatGPT, Gemini, Groq) ke free tier mein daily token aur message limits hoti hain, jabki user ke paas Gemini Pro ka active subscription aur Antigravity tatha OpenCode ka access maujood hai. In sabhi ko ek hi UI ke andar bina kisi API cost ke chalaane ke liye do-stariya (two-tier) routing mechanism ka upayog kiya jata hai. Pehle star par API aur local model management ke liye QuantumNous/new-api ya songquanpeng/one-api ko deploy kiya jata hai, jo ek single binary OpenAI-compatible gateway ke roop mein 20 se 30+ AI providers ko ek single local endpoint (/v1/chat/completions) ke peeche unify karta hai. Is gateway mein Gemini API, Groq ke free ultra-fast inference keys (Mankarjasika2506/civil-guru-ai ki tarah), aur local Ollama models ko "Channels" ke roop mein joda jata hai. Jab kisi ek channel ka free quota samapt hota hai, toh new-api ka intelligent load-balancer bina application workflow ko roke agle uplabdh free provider par request route kar deta hai.  
Doosre star par, jahan Claude.ai, ChatGPT web, aur Gemini web app ke free consumer quotas ya Gemini Pro web interface ka direct istemal karna ho, wahan API key ki jagah headless aur embedded browser automation lagaya jata hai. iFurySt/open-browser-use vishesh roop se Electron applications ke liye "Electron IAB (In-App Browser) MCP integration" (obu iab mcp) pradan karta hai. Yeh tool user ke asli Chrome profile ya Electron ke hidden \<webview\> session mein pehle se logged-in ChatGPT, Claude, aur Gemini web interfaces ko background mein Chrome DevTools Protocol (CDP) ke zariye control karta hai, prompt type karta hai, live DOM se markdown response extract karta hai, aur use seedhe UPSC JARVIS ke unified chat UI mein render kar deta hai. Iske alawa, static government portals ya coaching websites jinka DOM structure baar-baar nahi badalta, wahan runtime par LLM calls kharch karne ke bajaye crafter-station/webctl ka upayog kiya jata hai. webctl recon command ek baar Chromium khol kar traffic aur CSS selectors ka JSON Intermediate Representation (IR) banata hai aur webctl install ke zariye 300KB ka deterministic Rust CLI binary generate kar deta hai, jisse runtime par zero LLM calls mein sara data extract ho jata hai. Security ke drishtikon se, system mein browser-use library ka version 0.1.45 ya usse naya rakhna anivarya hai taaki CVE-2025-47241 (jismein URL ke authority component mein @ userinfo ke zariye allowed\_domains restriction bypass ho sakta hai) se poori tarah suraksha rahe.

### **LightRAG Knowledge Graph: Context Limit aur Parallel Processing ka Permanent Hal**

Bade PDFs (jaise Laxmikanth, Spectrum, ya Economic Survey) ko baar-baar AI ke prompt window mein bhejne se free quota turant khatam ho jata hai. Iska permanent samadhan HKUDS/LightRAG hai, jo Microsoft GraphRAG ka ek behad tez aur lightweight vikalp hai. Traditional vector RAG (jo sirf isolated text chunks match karta hai) ke viparit, LightRAG ek Dual-Layer Knowledge Graph Architecture banata hai jo local aur global dono contexts ko sambhalta hai. Jab koi NCERT ya standard reference book system mein ingest ki jati hai, toh LightRAG pehle document ko chhote segments mein baant kar LLM ki madad se Entities (jaise *"Article 356"*, *"Sarkaria Commission"*, ya *"Monetary Policy Committee"*) aur unke beech ke Relationships (edges) ko extract karta hai. Iske baad LLM-empowered profiling function har entity node aur relation edge ke liye ek संक्षिप्त Key-Value summary pair generate karta hai, aur built-in deduplication algorithm alag-alag kitabon ke chapters mein aane wale saman entities ko merge karke graph operation ke overhead ko ghata deta hai.  
LightRAG paanch vishesh query modes (local, global, hybrid, naive, aur mix) support karta hai, jismein local mode specific facts aur concrete concepts ke liye upayukt hai, global mode multi-hop subgraphs ke zariye macro themes aur cross-document trend analysis nikalta hai, aur default mix mode vector chunks tatha graph relationships dono ko jodkar sabse samagra uttar deta hai. Iska KV\_STORAGE aur VECTOR\_STORAGE backend LLM response caches, text chunks, aur entity-relation graphs ko PostgreSQL (pgvector \+ Apache AGE graph extension, jiska poora binary distribution matra 40MB mein zip ho jata hai) mein permanently save kar leta hai. Question-answer caching (enabled: true aur similarity\_threshold) active karne par milte-julte sawalon ke liye naye LLM call ki avashyakta hi nahi padti. Jab bahut saari PDFs ya current affairs files ki heavy parallel processing karni ho, tab LightRAG ke concurrency environment variables—jaise MAX\_ASYNC\_LLM, EXTRACT\_MAX\_ASYNC\_LLM, MAX\_PARALLEL\_INSERT (jise ideally MAX\_ASYNC\_LLM ka 1/3 rakha jata hai), MAX\_PARALLEL\_PARSE\_DOCLING, aur EMBEDDING\_BATCH\_NUM—ko local Ollama embedding model (nomic-embed-text jiska context size num\_ctx: 32768 tokens par set hota hai) ke saath configure karne par hazaron pages bina kisi cloud API limit ke background mein index ho jate hain.

## **Unified Brain (JEV Model) aur Prelims Trap-Decoding Engine**

Application ka central decision-making engine—jise "JEV (Judgment, Evaluation & Verification) Brain" kaha ja sakta hai—ek hybrid Small Language Model (SLM) architecture par kaam karta hai. Kisi bhi sadharan laptop par bina GPU bottleneck ke chalne ke liye Ollama ke madhyam se Microsoft ka Phi-3 Mini, भारतीय bhashaon aur terminologies ke sookshm nuances ke liye Sarvam-1 (projectvishwagyan-source/LLM-RAG), aur local multimodal tasks ke liye Qwen3.6-35B-A3B upayog kiya jata hai. Is local brain ko amanbh2/UPSC-Star, iaseth/prelimspattern, aur Mankarjasika2506/civil-guru-ai ke structured PYQ datasets se seedha joda jata hai.

### **End-to-End Syllabus Micro-Theme Tracking aur Direction Audit**

Aksar aspirants sirf "Polity" ya "Economy" likhkar padhai karte hain, jisse unhe yeh andaza nahi lagta ki exam ke asli micro-themes cover hue ya nahi. JEV Brain poore UPSC syllabus (Prelims \+ GS Papers 1–4 \+ Essay \+ Optional) ko granular micro-themes (jaise \#Polity\_Parliament\_MoneyBill, \#Polity\_Parliament\_Bills, ya \#Economy\_RBI\_Liquidity) aur 5 core Economy pillars (Monetary Policy, Fiscal Policy, External Sector, Sectors of Economy, aur Infrastructure/Schemes) mein vibhajit kar deta hai. Jab bhi student koi current affairs article ya PDF padhta hai, JEV model "Reverse-Tracking Logic" lagata hai: udaharan ke liye, yadi student kisi nayi mRNA vaccine ke baare mein news padh raha hai, toh JEV model turant check karta hai ki student ne NCERT Biology se *T-cells* aur *B-cells* ka static foundation cover kiya hai ya nahi, kyunki UPSC current news ko sirf inspiration banata hai jabki asli sawal static textbook se puchta hai. Isi tarah, yadi student medieval history ke obscure rajas ke naam yaad karne mein mahino laga raha hai jabki high-yield recurring themes jaise Buddhism, Jainism, administrative terminology, ya Geography ke agricultural aspects chhoot rahe hain, toh JEV model dashboard par turant "Direction Drift Alert" jari karta hai.

### **Prelims PYQ Trap Detection aur Logical Deduction Matrix**

Prelims mein asafalta ka sabse bada karan gyan ki kami nahi, balki examiner ke psychological traps mein phasna aur negative marking ke darr se 65 se kam sawal attempt karna hai. JEV Brain ko pichle 25–30 saalon ke PYQs (Polity aur History ke liye 25–30 saal, aur anya vishayon ke liye 10–15 saal) ke pancho core analytical patterns par train kiya jata hai. Sabse pehla niyam **Extreme & Sweeping Modifiers ("Kill the Extremes First")** ki pehchan hai: UPSC ke sahi statements mein hamesha nuance aur exceptions ki gunjaish hoti hai, isliye jab kisi statement mein *All, Every, None, No, Never, Always, Steady, Consistently, Alone, Only* jaise sweeping shabd aate hain (jaise *"All carbon compounds are organic in nature"* ya *"The RBI always reduces interest rates during inflation"*), toh JEV model unhe turant suspect mark karke eliminate karne ki training deta hai. Doosra niyam **Decade-Trend aur Data Direction Fallacy** hai: UPSC kabhi exact decimal figures nahi puchta balki data ki *direction* (increasing ya decreasing) par sawal banata hai, aur pichle 10 saalon mein kisi macroeconomic indicator ke lagatar ek hi disha mein badhne (*"Indian GDP growth rate has consistently increased over the last ten years"*) wale statements lagbhag hamesha galat hote hain kyunki economic growth kabhi linear nahi hoti.  
Teesra mahatvapoorna pattern **Possibility vs. Denial Asymmetry** hai: Science & Technology tatha Environment ke multi-statement questions mein kisi takneek ke sambhavit upayog (*possibility*) ko nakaarne ke liye examiner ko 100% thos praman chahiye hota hai, isliye sambhavna jatane wale statements aksar sahi hote hain aur sambhavna ko nakaarne wale statements galat hote hain unless woh bilkul absurd hon. Chautha niyam **Word Substitution aur Internal Contradiction Traps** ko pakadna hai, jahan examiner mashhoor concept (jaise *Fly Ash*) ke applications dekar upar shabd badal kar *Copper Slag* kar deta hai, ya do mutually contradictory statements (jaise Option 2 aur Option 4\) ek saath rakh deta hai jinmein se dono ek saath sahi nahi ho sakte. Paanchwa niyam **Sovereignty, Binding Treaty aur Institutional Tone Filter** hai: PYQ trends ke anusar UPSC kabhi bharat sarkar ya Urban Local Bodies (ULBs) ke prayason ko bilkul nakaratmak (negative light) mein portray nahi karta, UN treaties ko "legally binding" batane wale statements aksar galat hote hain, aur kisi international treaty dwara kisi desh ke *internal migration* ko regulate karne ka dawa desh ki sovereignty ke khilaf hone ke karan asatya hota hai.  
Top-ranker precision develop karne ke liye JEV Brain student ke PYQ abhyas ko 9-minute प्रति MCQ ke rigid workflow mein dhalta hai, jismein 2 minute initial solving (stamina aur focus banane ke liye), 5 minute post-solve analysis (examiner ke logic aur traps ko samajhne ke liye), aur 2 minute note-making (quick revision ke liye keywords darj karne) par lagaye jate hain. Saath hi, har mock ya PYQ attempt karte waqt UI mein **Green, Amber, aur Red Color-Tagging** anivarya hoti hai. Student jin sawalon par 100% nishchit hota hai unhe Green (jahan 90%+ accuracy aati hai), 50-50 elimination wale sawalon ko Amber (60–70% accuracy), aur pure guess zone wale sawalon ko Red (matra 10–30% accuracy) tag karta hai. JEV Brain student ko pichle 10 saal ke papers kam se kam teen iterations mein (pehli baseline knowledge ke liye, doosri textbook source mapping ke liye, aur teesri option trap psychology ke liye) solve karwata hai aur use 75 se 85 questions ke optimal mathematical buffer mein attempt karne ke liye calibrate karta hai.

## **Telegram Crawler, Obsidian Second Brain aur Automated Activity Tracking**

UPSC ka lagbhag sara digital study material (standard books, coaching notes, newspapers, aur topper copies) Telegram channels par circulate hota hai. Student ko baar-baar Telegram khol kar social media distractions ka samna na karna pade, iske liye UPSC JARVIS mein randaft20-cloud/Telegram-media-downloader, Dineshkarthik/telegram\_media\_downloader, aur yousofss/telegram-media-downloader (ya restricted groups ke liye Neet-Nestor/Telegram-Media-Downloader) ko backend microservice ke roop mein integrate kiya jata hai.

### **Direct Telegram-to-Obsidian Vault Sync Pipeline**

Application ke onboarding aur Settings interface mein user apna personal Telegram api\_id, api\_hash (jo my.telegram.org se prapt hota hai) aur phone number enter karke OTP ke zariye login karta hai. System official Telethon library ke madhyam se 100% local session file banata hai jisse sara data user ki machine par hi rehta hai aur kisi third-party cloud ki zaroorat nahi padti. Setup ke dauran app user se puchta hai ki woh apne downloaded PDFs aur study materials ko kis local directory mein store karna chahta hai. User dwara chune gaye folder path ko config.yaml mein download\_directory ke roop mein save kar diya jata hai, aur UPSC JARVIS usi folder ko seedhe student ke **Obsidian Vault** ("AI Second Brain") ke roop mein link kar deta hai.  
User app ke UI dropdown se apne joined UPSC channels ya groups select karta hai aur file-type filter ko .pdf, .docx, ya .zip par set kar deta hai. Dineshkarthik/telegram\_media\_downloader ka state-separation mechanism har channel ke liye last\_read\_message\_id ko config file mein track karta hai, jisse incremental sync hota hai aur pehle se download ki gayi PDFs dobara download nahi hoti. Saath hi, asyncio.gather ke zariye multiple chats se parallel downloading hoti hai jabki max\_concurrent\_downloads aur download\_delay (fixed ya random delay) parameters user ke Telegram account ko FloodWait ya rate-limit ban se surakshit rakhte hain. Jaise hi koi nayi PDF Obsidian vault folder mein aati hai, datalab-to/marker use high-accuracy Markdown aur JSON mein convert karke structured metadata.json catalog (abhinavsricharan/local-rag-bot ki tarah) se jod deta hai. Obsidian vault ke andar open-spaced-repetition/obsidian-spaced-repetition-recall aur ai-learning-tools/obsidian-spaced-repetition-ai plugins pehle se active rehte hain, jo single-line, multi-line, aur cloze flashcards ke saath-saath poore notes ka forgetting curve ke viruddh spaced repetition schedule tayyar kar dete hain.

Agar user koi badlav nahi karta, toh system default UPSC examiner rubric par kaam karta hai.

Har window mein alag kitab ka wahi specific page khulta hai, aur AI khud us page par woh exact line ya paragraph highlight kar deta hai jahan se UPSC mein PYQ pucha gaya tha, saath hi us highlighted paragraph ke bagal mein exact PYQ question aur uska saal (year) tag kar deta hai.

### **Handwritten Copy Ingestion aur Strict Multi-Parameter Audit**

Student kagaz par apna uttar likhkar uski photo app mein upload karta hai. Is handwritten copy ko process karne ke liye Vik Paruchuri ke datalab-to/chandra (12.6k+ GitHub stars wala specialized OCR model jo complex tables, forms, aur handwriting ko full layout ke saath samajhta hai) aur datalab-to/surya ka istemal kiya jata hai. chandra student ki copy se handwritten text, subheadings, margins, aur diagrams extract karta hai, jiske baad thisisAtharv/ExamEdge (Shastra-inspired handwritten answer evaluator) aur laleetborse/UPSC-Answer-Generator (Google Gemini par aadharit official UPSC answer framework) us par kadi jaanch chalate hain.  
AI reviewer bina kisi riyayat (no mercy) ke copy ka harek पहलू jaanchta hai: kya introduction 2 lines mein crisp data ya background ke saath likha gaya hai; kya body mein multi-dimensional subheadings aur logical bullet points hain; aur kya conclusion 2 lines mein optimistic vision tatha authentic committee ya government report (jaise 2nd ARC, NITI Aayog, ya Law Commission) ke reference ke saath samapt hua hai? Iske alawa, local grammar aur phrasing engine (QuietPrompt ya offline Ollama grammar-correction assistant ki tarah) har grammatical mistake, spelling error, aur weak sentence structure par marks kaat-ta hai aur batata hai ki kis point par examiner marks katega. Handwriting ki safai aur readability sudharne ke liye, jahan bhi chandra aur surya OCR ka line/word detection confidence girta hai, AI un gande likhe shabdon ko red box mein highlight karta hai aur student ke liye ek customized **"Handwriting Practice & Remediation Sheet"** generate karta hai taaki woh un specific shabdon aur अक्षरों ko saaf aur readable likhne ka abhyas kar sake.

## **Silent AI Interview Simulator: Computer Vision aur Acoustic Prosody Analysis**

UPSC Personality Test ki taiyari ke liye app mein ek unूठा **Silent AI Interview Simulator** hota hai, jismein obligator11/InterviewAnalyzer, Akshit-Srivastava1/AI-Interview-Platform, YugPatel11/NeuroVoxis, mrgulrez/haven-ml, aur hacked2026-githappens/git-happens\_speaksmart ke computer vision aur audio pipelines ko ek saath joda gaya hai. Is mode mein AI bilkul nahi bolta—screen par DAF aur current affairs se juda sawal text ke roop mein ubharta hai, aur candidate webcam ke samne baith kar apni aawaz mein jawab deta hai jabki AI chupchap use dekhta aur sunta hai.

### **Computer Vision (MediaPipe) aur Audio Prosody Pipeline**

Jawab dete samay candidate kaise baitha hai, kahan dekh raha hai, aur kaise bol raha hai, iska real-time biometric vishleshan OpenCV (opencv-python) aur Google MediaPipe (google-ai-edge/mediapipe) ke teen parallel solutions dwara kiya jata hai. Sabse pehle **Eye Contact aur Head Pose Analysis** ke liye mp.solutions.face\_detection (jo chehre ke 6 key landmarks track karta hai: Right Eye 0, Left Eye 1, Nose Tip 2, Mouth Center 3, Right Ear 4, aur Left Ear 5\) tatha MediaPipe FaceMesh \+ Dlib (hadi-mostafa-27/Student-Engagement-Detection-System-using-Head-pose-and-Eye-Gaze-) ka upayog karke candidate ki gaze estimation aur camera ke prati eye contact percentage maapa jata hai. Doosre star par **Sitting Posture aur Hand Gesture Tracking** ke liye mp.solutions.pose candidate ke skeletal points aur spine alignment ko track karke sitting confidence nikalta hai, jabki mp.solutions.hands hatheli aur ungliyon ke 21 joints (Wrist 0, Thumb 1–4, Index 5–8, Middle 9–12, Ring 13–16, aur Pinky 17–20) ko track karke nervous fidgeting ya excessive gesture energy ko pakadta hai.  
Teesre star par **Voice, Tone aur Acoustic Prosody Evaluation** ke liye FFmpeg audio samples extract karke pitch, volume fluctuation, aur vocal stability ka vishleshan karta hai (git-happens\_speaksmart aur haven-ml ki tarah), jabki offline GGML Whisper / Groq Whisper speech-to-text transcription aur acoustic prosody validation karta hai. Transcript aur prosody metrics ko LLM (Groq/Gemini) ke paas bheja jata hai jo jawab ki factual accuracy, constitutional ethics, diplomatic balance, aur bolne ke tone (kya aawaz mein dar, hichkichahat, ya arrogance tha) ka "no mercy" mulyankan karke live predicted interview score aur frame-by-frame feedback report deta hai.

## **Distraction-Free Integrated Browser, Current Affairs Engine aur Top-Ranker Habit Architecture**

### **Brave-Style Adblocking aur YouTube Shorts Lockdown**

Is integrated browser mein Brave browser jaisa ad-free anubhav dene ke liye Electron ke main.js mein Ghostery/Cliqz ki @cliqz/adblocker-electron (^1.26.16 ya ^1.33.2) aur @cliqz/adblocker-electron-preload library ko cross-fetch ke saath joda jata hai. YouTube Shorts aur irrelevant videos ko poori tarah ban karne ke liye Electron ke preload.js mein DOM filter lagaya jata hai jo Shorts shelves aur recommendation sidebars ko block kar deta hai, aur JEV Brain ke Keyword LLM ke zariye sirf UPSC syllabus se jude lectures ko hi play hone ki anumati milti hai. ## **Advanced Top-Ranker Features (Brainstormed High-Yield Additions)**

Ek sadharan aspirant ko top-ranker mein badalne ke liye UPSC JARVIS mein paanch aise advanced pedagogical modules jode gaye hain jo parikshak (examiner) ki mansikta aur student ki cognitive weaknesses ko target karte hain:

### **1\. Distractor Deconstruction & Next-Year Question Predictor Engine**

UPSC Prelims ka sabse gehra pattern yeh hai ki pichle saal ke paper ke teen galat options (distractors) hi agle saal ke main questions bante hain, kyunki commission kabhi random options nahi banata balki syllabus ke relevant historical figures, scientific terms, ya acts ko hi options mein rakhta hai. JEV Brain pichle 15 saalon ke har Prelims PYQ ke teenon incorrect options ko अलग karke LightRAG ke zariye un par 100-word ke "Distractor Notes" banata hai, aur unhi themes (jaise 2023 mein Prisons Act 1894 puchne ke baad colonial-era laws undergoing reform ke pattern) par upcoming exam ke liye predicted questions generate karta hai.

### **2\. "Bouncer" Detection & Ego-Trap Simulator**

Har Prelims paper mein kuch sawal "Bouncers" hote hain—behad obscure facts jo kisi standard source mein nahi milte aur jinhe chhodna hi samajhdari hoti hai. App ke daily 30-MCQ active recall tests mein JEV Brain jaan-boojh kar 2–3 bouncer questions dalta hai taaki student ke اندر "Exam Sense" aur "Skip Instinct" viksit ho sake. Agar student un obscure bouncers par blind guess (Red Tag) lagata hai, toh app uspar भारी penalty lagata hai aur sikhaata hai ki top rankers har sawal chase nahi karte balki select karte hain.

### **3\. Dynamic DAF-2 & Cadre Current Affairs Matrix**

Interview ki taiyari aakhri mahine mein nahi ho sakti. Onboarding ke samay hi UPSC JARVIS student ke Detailed Application Form (DAF) ke विवरण—Home State, District, Graduation Subject, Hobbies, aur Service/Cadre Preferences—ko store kar leta hai. Iske baad ananyaem/UPSC-LL\[span\_110\](start\_span)\[span\_110\](end\_span)\[span\_112\](start\_span)\[span\_112\](end\_span)M aur nit-in/pib ke daily current affairs stream mein jab bhi student ke home state ya hobby se judi koi khabar aati hai, system use react interview-preparation civil-services upsc rag fastapi pgvector pipeline ke तहत student ke personal DAF Question Bank mein jod deta hai.

### **4\. Mistake Autopsy & Cognitive Bias Ledger**

Test dene ke baad ek ghanta baith kar apni galtiyon ka post-mortem karna behad zaroori hai. Jab bhi student koi MCQ galat karta hai, system use aage badhne se pehle us galti ko chaar categories mein classify karne ko kehta hai: *Conceptual Issue* (basic concept clear nahi tha), *Revision Deficit* (padha tha par bhool gaya), *Silly Mistake* (sawal mein "NOT" ya "incorrect" nahi padha), ya *Over-Application of Elimination Tricks*. Agar student ke basic conceptual questions galat ho rahe hain toh JEV Brain turant NCERT (nit-in/download\_ncert\_books) ka chapter reopen karwata hai, jabki current affairs ke obscure sawal galat hone par ghabrane se rokta hai kyunki Prelims concepts aur logic se nikalta hai.

### **5\. Topper Copy "Git-Diff" Visual Comparator**

Jab student Mains ka uttar upload karta hai, toh system datalab-to/chandra se digitized kisi UPSC Topper ki usi topic wali answer copy ko student ki copy ke barabar mein split-window mein khol deta hai. Isse student ko turant dikh jata hai ki jahan usne 150 words ka lamba paragraph likha, wahan topper ne ek chhota hub-and-spoke diagram, map, aur 4 crisp subheadings banakar 2 extra marks hasil kar liye.
